# 内容筛选与注意力预算

在完整读取 transcript 后、形成正文大纲前读取本文件。目标是让每一段都为读者提供主旨、机制、证据、边界或行动价值上的理解增量。

## 1. 建立主问题

先用一句话写出视频试图回答的主问题，再列出 3–8 条候选核心结论。主问题用于校准取舍；候选结论用于检查主线覆盖。

对每个候选片段执行删除测试：

> 移除这段后，读者对主旨、机制、证据、边界或行动价值的理解是否下降？

理解明显下降时保留并给予相称篇幅；理解仍完整时省略或合并到一句背景中。

## 2. 内容分级

### 核心

满足至少一项：

- 定义视频的主张、问题或结论。
- 解释关键机制、因果链、方法步骤或决策原则。
- 提供支撑主张的关键数据、演示、案例或反例。
- 界定方法的适用条件、失败模式、代价或影响。
- 提供可迁移且与主旨紧密相连的实践方法。

核心内容获得主要篇幅。每个复杂核心点应说明结论、机制或推理、代表性证据、重要性以及适用边界。重点内容只有一句话时，回到 transcript 补齐其论证链。

### 支撑

用于理解核心内容的术语定义、必要背景、代表性数字、关键案例或因果前提。保留对当前核心点有直接作用的部分，通常压缩为一两句或一个短列表。

人物经历只有在它解释观点来源、方法形成、约束条件或结果差异时进入支撑层。产品名、团队名和时间线按其解释价值取舍。

### 外围

常见类型包括录制故障、Zoom 或麦克风插曲、寒暄、玩笑、普通转场、主持人重复确认、弱因果的职业轶事、命名趣闻、结束宣传和已经表达过的结论。

默认总结省略外围内容。`detailed` 模式仅在外围片段揭示人物动机、关键约束、可信度或主旨反例时吸收其有效部分。

## 3. 问答改写

访谈的对话顺序服务于观看体验；总结的结构服务于理解。

- 普通提问只承担换题作用时，直接使用答案的结论作为小标题。
- 提问揭示关键异议、反例、误区或限制时，保留其问题含义，并压缩主持人的原话。
- 回答分散在多轮对话中时，合并成一个连贯论点，并保留覆盖这些轮次的时间区间。
- 嘉宾回避问题或不同说话者存在冲突时，保留对话关系与观点归属。

示例：使用“Token 成本与适用边界”作为章节主题，比记录“主持人询问 Token 成本”更节省注意力。

## 4. 结构与篇幅

先按主线组织章节，再在章节内恢复时间顺序。小标题表达结论，正文解释推理，**列表整理并列项**。**鼓励使用换行、分段、有序或无序列表、表格、强调等结构化输出来方便读者快速阅读**。


示例：
```
...
动手前先回答六个问题：谁需要这个功能、他们今天的痛点是什么；仍然真正有用的最简版本（MVP）长什么样；哪些进 V1、哪些放以后；它如何与现有应用契合（认证、计费、权限、既有 UI）；从用户视角看成功标准是什么；以及最重要的——哪些东西明确属于范围外。作者反复强调：想清楚要构建什么和放弃构建什么，是工程师理解问题的前提。
...
```
上面用分号(或顿号)分隔的句子，很适合用列表来展示:
```
...
动手前先回答六个问题：
- 谁需要这个功能、他们今天的痛点是什么；
- 仍然真正有用的最简版本（MVP）长什么样；
- 哪些进 V1、哪些放以后；
- 它如何与现有应用契合（认证、计费、权限、既有 UI）；
- 从用户视角看成功标准是什么；
- 以及最重要的——哪些东西明确属于范围外。

作者反复强调：想清楚要构建什么和放弃构建什么，是工程师理解问题的前提。
...
```

**文笔精炼、直接、自然，这样才方便读者快速阅读**。

详略模式控制支撑层密度：

| 模式 | 核心内容 | 支撑内容 | 次级论点 | 典型用途 |
|---|---|---|---|---|
| `concise` | 全部保留，压缩表达 | 只留必要前提与强证据 | 少量 | 快速浏览 |
| `balanced` | 全部展开到足以理解 | 适量保留 | 保留直接影响主线者 | 默认综合总结 |
| `detailed` | 全部深入展开 | 较完整 | 保留重要分支 | 研究、复盘、技术学习 |

同一结论在概览、正文、关键结论和 Take-away 之间采用递进关系：概览给结论，正文给论证，Take-away 给应用。大段同义复述应合并。

## 5. 证据与总结者扩展

写作时区分四类信息：

1. `视频陈述`：说话者明确表达的观点、事实或数字。
2. `画面观察`：总结者实际看见的界面、图表、代码、动作或文字。
3. `辅助理解`：帮助读者理解概念、隐含推理或背景关系的解释。
4. `基于视频的落地建议`：总结者延伸出的指标、实施步骤、评估方法或工程建议。

前两类注明人物、时间区间或画面来源；后两类使用明确标签，并说明证据连接与适用条件。数字要核对单位和对象，例如 PR、commit、issue、百分比和时间跨度。

## 6. 终稿审计

按以下权重审视终稿：

- 相关性与注意力效率：25%
- 核心覆盖与论证深度：25%
- 结构化与可扫读性：15%
- 观点归属与可追溯性：15%
- 辅助理解与 Take-away 的增量：10%
- 视觉证据价值与清晰度：10%

终稿应满足这些硬门槛：

- 所有核心结论都有时间范围与充分解释。
- 外围内容只在提供明确理解增量时出现。
- 关键数字、专有名词和因果关系经过素材交叉核对。
- 总结者扩展具有标签，视频原意与延伸建议保持清楚边界。
- 视觉证据只服务于强依赖画面的核心结论，并通过核心性、不可替代性、信息增量与可读性门槛。
- 每张截图具有实际查看后的观察记录；关键文字在最终展示尺寸可读，清晰度升级只作用于该时间点。
- Take-away 能回溯到正文，且与结尾总结各司其职。

完成条件：内容地图中的每个核心点已进入正文，每个支撑点都有明确用途，正文之外的素材都已通过删除测试完成取舍。
