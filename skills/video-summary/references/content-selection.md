# 内容筛选与长字幕分流

在读取 transcript 正文前读取本文件。目标是完整覆盖素材，同时把主 agent 的工作上下文集中在主线、证据和边界上。

## 1. 选择读取路径

先读取 `transcript.active.index.json`。用顶层 `segment_count` 和各 `chunks[].character_count` 的总和估算规模：

- `segment_count <= 1500` 且总字符数 `<= 60000`：直接读取 `transcript.active.md`，随后形成内容地图。
- 任一指标超过阈值：使用分块内容地图。剩余上下文较紧时可以提前采用该路径。

### 分块内容地图

按 index 中的连续 chunks 调用：

```bash
python3 <skill-dir>/scripts/acquire_video.py transcript-slice \
  --input '<work-dir>/transcript.active.jsonl' \
  --segment-start <start> --segment-end <end>
```

每个 active segment 恰好进入一次首次阅读范围。每读完一个 chunk，立即向 `<work-dir>/content-map.chunks.jsonl` 追加一条紧凑记录：

```json
{
  "chunk": 0,
  "segment_start": 0,
  "segment_end": 199,
  "time_range": "00:00:00–00:12:40",
  "claims": [{"text": "…", "evidence_segments": [31, 38]}],
  "boundaries": ["…"],
  "examples": ["…"],
  "visual_signals": [{"time": "00:08:12", "reason": "界面演示"}],
  "peripheral": ["寒暄与普通转场"]
}
```

记录主张、证据位置、适用边界、代表性例子和视觉信号。外围内容只记录类别。环境支持 subagents 时，将互不重叠的 chunk 组分配给最多四个 worker；每个 worker 只返回块级记录。主 agent 检查 segment 范围连续、首尾完整且无重复。

汇总块级记录形成 `<work-dir>/content-map.json`。写作阶段针对入选的重点证据重新调用 `transcript-slice`；引用、数字、专有名词和复杂因果优先复读原文。

## 2. 建立主问题

完成素材覆盖后，用一句话写出视频试图回答的主问题，再列出 3–8 条候选核心结论。对每个候选片段执行删除测试：

> 移除这段后，读者对主旨、机制、证据、边界或行动价值的理解是否下降？

理解明显下降时保留并给予相称篇幅；其余内容省略或压缩为必要背景。

## 3. 内容分级

### 核心

满足至少一项：

- 定义视频的主张、问题或结论。
- 解释关键机制、因果链、方法步骤或决策原则。
- 提供支撑主张的关键数据、演示、案例或反例。
- 界定方法的适用条件、失败模式、代价或影响。
- 提供与主旨紧密相连的可迁移实践。

核心内容获得主要篇幅。复杂核心点说明结论、机制或推理、代表性证据、重要性和适用边界。重点内容只有一句话时，返回对应 transcript slice 补齐论证链。

### 支撑

支撑内容包括术语定义、必要背景、代表性数字、关键案例和因果前提。保留对核心点有直接作用的部分，通常压缩为一两句或一个短列表。

人物经历在解释观点来源、方法形成、约束条件或结果差异时进入支撑层。产品名、团队名和时间线按解释价值取舍。

### 外围

常见类型包括录制故障、Zoom 或麦克风插曲、寒暄、玩笑、普通转场、主持人重复确认、弱因果职业轶事、命名趣闻、结束宣传和同义重复。

默认总结省略外围内容。`detailed` 模式可以吸收其中揭示人物动机、关键约束、可信度或主旨反例的有效部分。

## 4. 问答与结构

- 普通提问只承担换题作用时，直接使用答案结论作为小标题。
- 提问揭示关键异议、反例、误区或限制时，保留问题含义并压缩主持人原话。
- 回答分散在多轮对话中时，合并成一个连贯论点并使用覆盖这些轮次的时间区间。
- 嘉宾回避问题或说话者观点冲突时，保留对话关系与观点归属。

先按主线组织章节，再在章节内恢复时间顺序。概览给结论，正文给论证，Take-away 给应用。段落解释推理；列表整理步骤和并列项；表格承载稳定的多字段比较。

### 结构化改写

一个句子包含三个以上并列的问题、步骤、规则、标准或选项时，拆成有序或无序列表。保留列表前的总括句和列表后的核心结论。

例如，将：

> 动手前先回答六个问题：用户是谁、当前痛点是什么；真正有用的 MVP 长什么样；哪些进入 V1；如何与现有系统结合；成功标准是什么；哪些内容属于范围外。

改为：

> 动手前先回答六个问题：
>
> - 用户是谁，当前痛点是什么；
> - 真正有用的 MVP 长什么样；
> - 哪些进入 V1；
> - 如何与现有系统结合；
> - 成功标准是什么；
> - 哪些内容属于范围外。
>
> 这些问题共同用于明确构建范围和验收标准。

通过换行、分段、有序或无序列表、表格和适量强调建立视觉层级，帮助读者快速定位信息。连续论证使用完整段落，保留推理关系。

## 5. 证据与总结者扩展

区分四类信息：

1. `视频陈述`：说话者明确表达的观点、事实或数字。
2. `画面观察`：总结者实际看见的界面、图表、代码、动作或文字。
3. `辅助理解`：帮助读者理解概念、隐含推理或背景关系的解释。
4. `基于视频的落地建议`：总结者延伸出的指标、实施步骤、评估方法或工程建议。

前两类注明人物、时间区间或画面来源；后两类使用明确标签，并说明证据连接与适用条件。数字核对单位和对象，例如 PR、commit、issue、百分比和时间跨度。

## 6. 终稿审计

按顺序检查：

1. 主线覆盖完整，所有核心结论具有时间范围和充分解释。
2. 核心论证包含必要的机制、证据、重要性与适用边界。
3. 支撑信息具有明确用途，外围信息通过删除测试。
4. 关键数字、专有名词和因果关系经过素材交叉核对。
5. 视频陈述、画面观察、辅助理解和落地建议归属清楚。
6. 标题、段落、列表和表格支持快速扫读，概览、正文与 Take-away 提供递进信息。

完成条件：`content-map.json` 覆盖全部 active segments；每个核心点进入正文；每个支撑点具有用途；终稿中的重点事实可以返回 transcript 或画面核查。
